# Llama 4：模块功能与调用说明

配套架构图覆盖公开的 Scout / Maverick 推理主干：**图文输入 → 视觉编码与文本嵌入 → Early Fusion → 自回归 Transformer → 文本输出**。图中箭头表示张量流向；循环箭头表示逐 token 生成。本文将架构含义与当前本地参考实现的调用方式对应起来。

源码依据：Meta `llama-models`，本地提交 `0e0b8c519242d5833d8c11bffc1232b77ad7f301`（简称 `0e0b8c5`）。下方源码链接相对于本文件，标签标明实际行号。

## 1. 从输入到输出

```text
Llama4.chat_completion(messages)
  └─ ChatFormat.encode_dialog_prompt()
       ├─ 文本：Tokenizer.encode() → token IDs
       └─ 图片：RGB → 等比例缩放 / 填充 / 分块 / 归一化
                 → 多块图片时补充全局缩略图 → 图像占位 token
  └─ Llama4.generate()
       ├─ 首次 prefill：VisionEmbeddings.forward()
       │    └─ VisionEncoder → PixelShuffleMLP → scatter_embeddings
       ├─ Transformer.forward()
       │    └─ 文本 Embedding + 视觉 Projection
       │         → 在 <|patch|> 位置替换为视觉向量（Early Fusion）
       │         → TransformerBlock × L
       │         → RMSNorm → LM Head → logits
       └─ 温度 / top-p 采样，或 argmax → 下一个 token → 解码
            └─ 携带 KV Cache，继续 Transformer.forward()
```

入口见 [generation.py:269](../../llama-models/models/llama4/generation.py#L269)，生成循环见 [generation.py:183](../../llama-models/models/llama4/generation.py#L183)。图片在首轮 prefill 编码，后续 token 通过缓存的 K/V 继续利用已有图文上下文。

视觉分支的注意力是 MHA；语言主干的注意力是 GQA。Early Fusion 发生在进入语言 Transformer 之前，视觉与文本随后组成同一序列。

## 3. MoE 的门控位置

令 `x` 为 MoE 收到的 token 向量，`s = xW_router`，Top-1 路由下：

```text
e = argmax(s)                  选中的路由专家
g = sigmoid(s_e)              选中专家的门控值
y = Shared(x) + Expert_e(g·x) 两个分支相加
```

**该参考实现先用 `g` 缩放路由专家的输入，再执行专家网络。** 共享专家直接接收 `x`。SwiGLU 专家含非线性，因此 `Expert_e(g·x)` 与 `g·Expert_e(x)` 一般不相等。图中的门控应放在路由专家之前。依据 [moe.py:181](../../llama-models/models/llama4/moe.py#L181) 与 [moe.py:198](../../llama-models/models/llama4/moe.py#L198)。

专家内部的计算为 `SwiGLU(x) = (SiLU(xW₁) ⊙ xW₃)W₂`。语言 Transformer 层的完整残差关系是：

```text
h   = input + Attention(RMSNorm(input))
out = h     + FFN_or_MoE(RMSNorm(h))
```

共享专家与路由专家相加是 MoE 内部操作；`h + ...` 是外部残差，图中应分别表示。Top-1 表示逻辑路由；这份参考代码会把未选中分支的输入置零后送入批量专家计算，不能据此宣称其计算内核只执行一个专家。

## 4. Prefill、解码与本地实现边界

首次 prefill 处理提示词与图像占位序列。`generate()` 在 `prev_pos == 0` 时计算图像嵌入；每个语言注意力层把当前序列的 K/V 写入自己的缓存。后续通常每轮输入一个新 token，读取缓存前缀、预测下一个 token，直到停止标记或长度上限。见 [generation.py:186](../../llama-models/models/llama4/generation.py#L186) 与 [model.py:234](../../llama-models/models/llama4/model.py#L234)。

注意力细节按这个提交解释：

- `Transformer.forward()` 仅在 `seqlen > 1` 时建立全局因果与局部分块掩码；局部分块是互不重叠的块内因果注意力。代码位置：[model.py:407](../../llama-models/models/llama4/model.py#L407)、[model.py:431](../../llama-models/models/llama4/model.py#L431)。
- 单 token 解码时掩码为 `None`，K/V 缓存读取整个已处理前缀；因此该提交的局部分块限制没有在单 token 解码路径中继续施加。此时缓存本身只含过去与当前 token，因果性仍成立。架构图描述 iRoPE 的设计分工，不能将这段参考解码代码解释为始终执行严格分块注意力。
- NoPE 层在此实现中同时关闭 RoPE 与 QK Norm；如果配置开启推理时注意力温度调节，调节施加于 NoPE 层的 Q。它与输出采样的 `temperature` 是两个不同位置的机制。见 [model.py:260](../../llama-models/models/llama4/model.py#L260)、[model.py:220](../../llama-models/models/llama4/model.py#L220)。

## 5. Scout / Maverick 与图中数字

| 项目 | Scout | Maverick |
|---|---:|---:|
| 每个 MoE 层的路由专家池 | 16 | 128 |
| 每个 token 的激活参数量 | 17B | 17B |
| 总参数量 | 109B | 400B |
| 模型卡上下文长度 | 10M tokens | 1M tokens |
| 输入 / 输出 | 文本与图片 / 文本与代码 | 文本与图片 / 文本与代码 |

上述数字来自 [Meta 模型卡](https://github.com/meta-llama/llama-models/blob/0e0b8c519242d5833d8c11bffc1232b77ad7f301/models/llama4/MODEL_CARD.md#L11)。`16 / 128` 是路由专家池大小；共享专家另列。激活参数量为整个模型按 token 激活的规模，不能理解为单个专家大小。

层数、隐藏维度、注意力头数、视觉 patch 尺寸、Dense/MoE 排列、NoPE 间隔由具体 checkpoint 配置决定。此本地仓库不含 Scout / Maverick 的 `params.json`；`Llama4.build()` 从权重目录加载这些配置，再由调用方指定运行时 `max_seq_len`。因此图中未单独核验的尺寸用 `L`、`d` 或“按配置”表示，模型卡的最大上下文也不等于当前运行环境自动支持的长度。见 [generation.py:67](../../llama-models/models/llama4/generation.py#L67)。
